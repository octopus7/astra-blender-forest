# 검증 보고서 — 300m 패키지 v2.0.0

## 수행한 검증

| 검사 | 결과 |
|---|---|
| 패키지 Python 파일 문법 컴파일 | 통과 |
| 순수 Python 단위 테스트 | 30개 통과 |
| 기본 300m 씬 전체 생성 | 완료 |
| 전체 고유 메시의 인덱스·유효 숫자·색상·퇴화 삼각형 검사 | 오류 0개 |
| 모든 배치의 좌표 변환 및 셀 판정 | 16,573개 통과 |
| 일반 숲 나무 간격 및 물·길·예약 공간 회피 | 3,800개 통과 |
| 지형 전체 범위 | X/Y 각각 -150 ~ +150m |
| 셀별 그룹 배치 수량 합계 | 원본 16,573개와 일치 |
| 별도의 두 기본 생성 결과 통계 비교 | 일치 |
| 제공 미리보기의 원본 | 제공 코드로 생성한 실제 메시·트랜스폼 |

단위 테스트는 빠르게 반복하기 위해 60 × 60 지형 격자와 줄인 배치 수를 사용합니다. 이와 별도로 **기본 설정 그대로의 480 × 480 격자, 3,800그루의 숲, 전체 소품**을 생성하여 다시 검증했습니다.

단위 테스트에는 36개 지형 조각의 경계 높이 일치, 수면 삼각형 중복 방지, 난수 시드 재현, 랜드마크와 길의 근접성, 모델 ID 참조, 고유 메시 분리 없는 배치 레코드, 과수원 나무의 길 회피, 설정값 검증이 포함됩니다. 축 변환은 48가지 부호·축 순열을 비균등 스케일과 함께 검사합니다. 잘못된 단위 보정, 전단·음수 스케일·NaN 입력을 거부하는지도 검사합니다.

기본 생성 데이터 수량:

```text
고유 메시              127
배치 레코드          16,573
나무                  3,839  (소원 나무 포함)
고유 삼각형 합계     521,197
배치 포함 삼각형   4,807,521
목적지                   12
공간 셀                  36
```

`default_generation_stats.json`의 `estimated_*_actors` 값은 셀·모델별 묶음에서 계산한 예상치입니다. Unreal에서 생성된 액터 수를 측정한 결과가 아닙니다.

## 수행하지 못한 검증

**이 작업 환경에서는 Blender와 Unreal Editor를 직접 실행하지 못했습니다.** 따라서 아래는 미검증입니다.

- 실제 `bpy` API 실행, Blender 화면 표시·재질·렌더·저장.
- 실제 생성 씬의 Mesh 데이터블록 공유 상태 검사 스크립트 실행.
- 실제 FBX 파일 출력 및 엔진에서의 가져오기·축 보정.
- Unreal HISM SubobjectData API, 에셋 저장, 선택 셀 재배치의 실제 동작.
- 게임 플레이, 충돌, 프레임 속도, CPU/GPU·메모리 성능.

기하 데이터와 행렬 수학 검증이 통합 실행 검증을 대신하지는 않습니다. 실제 엔진에서 먼저 복사본 레벨로 시험해야 합니다. 실행 오류가 생기면 에디터 버전과 콘솔의 전체 오류 메시지를 기준으로 확인해야 합니다.

미리보기는 별도 CPU 렌더러의 근사 조명으로 만들었습니다. Blender / Unreal 렌더 결과로 표시하지 않습니다.

## 재현

Blender 없이 패키지 폴더에서 실행:

```sh
python -m unittest discover -s tests -v
python tests/validate_full_scene.py
```

두 번째 명령은 현재 `cozy_config.json`을 사용하여 새로 생성하고 `output/full_python_validation.json`에 보고서를 씁니다. 설정을 바꾸면 이 문서의 수량과 달라집니다. 지나치게 높은 나무 목표는 배치 간격 조건 때문에 전체 검증에서 실패할 수 있습니다.

이번 결과 원문:

- `tests/reports/unit_tests.txt`
- `tests/reports/full_python_validation.json`

보고서의 실행 시간은 이 환경에서의 순수 Python 생성·검사 시간이며 Blender 생성 시간이나 게임 성능이 아닙니다.
